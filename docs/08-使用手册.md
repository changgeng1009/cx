## 一、三种启动方式

### 方式 1：零安装（现在就能用，推荐）

```bash
cd /d D:\CodexWork\学习通刷课脚本
python -m orchestrator.cli <命令>
```

要求：Python ≥ 3.11（本机已装 3.13.13）。**不需要 `pip install` 任何东西**——统一层零第三方依赖。

### ⚠️ 先分清：哪个文件能双击

| 文件 | 能双击吗 | 用途 |
|---|---|---|
| **`启动独立浏览器.cmd`** | ✅ **双击这个** | 启动独立 Edge 去登录学习通 |
| `cx.cmd` | ❌ **不要双击** | 命令行入口，必须带命令名 |
| `python -m orchestrator.cli` | ❌ | 命令行入口（等价于 `cx`） |

**双击 `cx.cmd` 不会启动浏览器。** 它只是个命令入口，双击时没有参数，
所以只能打印一份引导。如果你双击了它，窗口现在会停住不关，把引导读完就明白了。

### 方式 2：便捷入口 `cx.cmd`（在终端里用，不是双击）

在终端（cmd / PowerShell / Git Bash）里：

```bash
cx cookies_login
cx list_courses
cx --help
```

`cx.cmd` 会自动查找 Python（项目 `.venv` → PATH 里的 `python` → `py` → 已知安装路径），不硬编码中文路径。

> ⚠️ 这个脚本**未在开发沙箱内实测**（沙箱禁止调用 `cmd.exe`）。若报"找不到 Python"，用方式 1。如果它成功运行了，麻烦告诉我一声。

### 方式 2b：双击启动浏览器（你要找的就是这个）

**这是"拉不起来浏览器"时最推荐的做法。** 双击项目根目录的 `启动独立浏览器.cmd`：

- 双击时父进程是 `explorer.exe`，**浏览器窗口不会被任何 Agent 会话回收**，能稳定留下
- 窗口结束前有 `pause`，输出不会一闪而过
- 内置 `chcp 65001`，中文不会乱码

它只做一件事：启动独立 Edge 并打开学习通登录页。登录完再跑 `cx cookies_login --no-open` 提取。

### 方式 3：正式安装

```bash
pip install -e .
orchestrator <命令>          # 等价于 python -m orchestrator.cli
orchestrator-mcp             # 启动 MCP Server
```

入口已在 `pyproject.toml` 声明（`orchestrator` / `orchestrator-mcp`），已验证可导入。

### 三种方式的关系

```
cx.cmd ─┐
        ├─► python -m orchestrator.cli ─► Orchestrator（同一套代码）
orchestrator ─┘
```

没有功能差异，只是敲起来长度不同。

## 二、第一步：登录拿 cookie

这是目前唯一需要你动手的环节，也是 M1 的门票。

```bash
cd /d D:\CodexWork\学习通刷课脚本

# 1) 起独立浏览器 + 等你登录 + 自动提取落盘（一条命令搞定）
cx cookies_login
```

会发生什么：

1. 启动一个**独立的 Edge 窗口**（profile 在 `.browser\edge-profile`，**不是你的日常 Chrome、也不是 Claude 在用的那个 Edge**）
2. 打开 `https://i.chaoxing.com`
3. 你在那个窗口里登录（扫码 / 密码都行，**密码不会经过本平台**）
4. 平台每 3 秒轮询一次，检测到 cookie 数量增长超阈值（默认 +3）就自动提取
5. 落盘到 `accounts\acc_01\cookies.{json,txt,header}` 三份

超时默认 300 秒。想调：

```bash
cx cookies_login --timeout 600          # 等更久
cx cookies_login --no-open              # 浏览器已经开着，不重复启动
cx cookies_login --min-delta 5          # 阈值调高，减少误判
cx cookies_login --port 9333            # 自定义 CDP 端口
```

### 然后验证会话真的有效

```bash
cx cookies_verify
```

这一步会**真实发一次 HTTP 请求**到 `https://i.chaoxing.com/base`，判定是四态：

| verdict | 含义 | 你该做什么 |
|---|---|---|
| `valid` | 命中登录后页面标记，会话可用 | 告诉我，我开始接 M1 |
| `invalid` | 被重定向到登录页，确实未登录 | 重新 `cookies_login` |
| `inconclusive` | 200 但识别不出标记 | **把输出贴给我**，补标记库 |
| `unreachable` | 网络不通 | 检查网络 / 代理 |

> **`inconclusive` 是预期内的**，因为我刻意只用结构性标记（`dataurl` / `mooc2-ans` / `账号：`），不用人名课名这类易变文本。第一次跑很可能命中它 —— 不代表登录失败。

### 如果不想开浏览器（B 路兜底）

从 Chrome/Edge 的 DevTools → Network → 任意请求 → 复制 `Cookie` 请求头的值：

```bash
cx cookies_import --header "UID=xxx; _d=yyy; fid=zzz" --source "devtools"
cx cookies_verify
```

`Cookie:` 头**没有域名信息**，所以缺域名的会被自动补 `.chaoxing.com`（可 `--domain` 覆盖）。

### cookie 组命令速查

| 命令 | 作用 | 需要浏览器 |
|---|---|---|
| `cookies_login` | 一站式：起浏览器 → 等登录 → 提取 | ✅ |
| `cookies_verify` | 真实请求一次平台，验证会话 | ❌ |
| `cookies` | 体检：看已落盘的 cookie（**掩码输出**） | ❌ |
| `cookies_extract` | 只做提取（浏览器已在运行时） | ✅ |
| `cookies_import` | 手动粘贴 / 从文件导入 | ❌ |
| `cookies_clear` | 清除已落盘的 cookie | ❌ |

### 浏览器拉不起来怎么办

**先说结论：跑诊断，不要猜。**

```bash
python -m orchestrator.browser --diagnose
```

它一次性检查全部环节（纯只读，不启动任何东西）：

| 检查项 | 为什么重要 |
|---|---|
| 浏览器可执行文件 | 找不到 → 用 `ORCH_EDGE_BINARY` 显式指定路径 |
| profile 路径 | 是否被隔离守卫拒绝、是否存在、是否可写 |
| 端口 | `9333` 是否已被别的程序占用 |
| CDP 端点 | 是否在线（**唯一有意义的是否存活判据**） |
| 上次启动记录 | PID 是否还活着 —— "启动后立刻死了"的指纹 |
| 浏览器日志 | **浏览器自己打印的话**，真正的失败原因通常在这里 |

最后会给出 `结论`，直接把"卡在哪一环"讲出来：

- `失败：端口 9333 已被占用` → 换端口：`--port 9334`
- `失败：上次启动的进程已退出，且 CDP 未就绪` → 看它下面附的 `log_tail`
- `失败：找不到 Edge 可执行文件` → 设 `ORCH_EDGE_BINARY`
- `未运行：浏览器当前没起来` → 正常状态，执行 `--launch` 即可

**最省事的做法：双击 `启动独立浏览器.cmd`。** 双击时父进程是 `explorer.exe`，
窗口不受任何 Agent 会话影响，能稳定留下。

> 为什么不能让我（Agent）帮你把窗口拉起来：我的执行环境在每次命令结束时
> 会回收子进程，所以浏览器能启动、CDP 能短暂在线，但窗口不会留下。
> 这一步必须由你在自己的终端或双击执行。

## 五、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| **浏览器窗口没出现** | 多种 | **先跑 `python -m orchestrator.browser --diagnose`** |
| 同上，且想省事 | — | 双击 `启动独立浏览器.cmd`（父进程是 explorer，窗口能留） |
| 报 `CDP_UNAVAILABLE` | 浏览器没起来/已退出/端口不对 | 同上；这**不是**登录问题，别去反复登录 |
| 报 `LOGIN_TIMEOUT` | 浏览器在，但等不到 cookie 增长 | 确认你是在独立窗口里登录（`auth` 类错误） |
| `ModuleNotFoundError: orchestrator` | 不在项目根目录 | `cd /d D:\CodexWork\学习通刷课脚本` |
| `cx` 命令找不到 | 没加进 PATH | 用 `.\cx.cmd` 或 `python -m orchestrator.cli` |
| CDP 连不上 | 浏览器没起来 | `python -m orchestrator.browser --launch` |
| `cookies_verify` 返回 `inconclusive` | 标记库没覆盖实际页面 | 把 `status`/`body_size`/`signals` 贴给我 |
| 报 `internal` + "上游依赖不可用" | worker 缺 `requests`/`pycryptodome` | `python -m pip install requests pycryptodome`（用运行 cx 的同一个解释器）；或直接用项目 `.venv` |
| 读命令返回空列表 | 上游对该课无章节/课表数据 | 正常现象，换个命令试试；确认 `adapter=xuexitong-mcp` |
| 写命令被拒绝 | 缺 `--confirm` | 加 `--confirm`（这是**故意的**安全门禁） |
| 想重来一遍 | cookie 脏了 | `cx cookies_clear` 后重新登录 |

> `CDP_UNAVAILABLE` 和 `LOGIN_TIMEOUT` 是**刻意分开**的两个错误码：
> 前者是"环境没就绪"（去把浏览器起起来），后者是"环境就绪但操作没完成"
> （去登录）。混在一起会让人对着一个"超时"反复重登，而真正的问题是
> 浏览器根本没起来。

**日志在哪**：`runs\` 下的 `*.jsonl` 是结构化日志，`*.raw.log` 是上游原始输出。每个请求一个 `request_id`，`cx --verbose` 会打到 stderr。
