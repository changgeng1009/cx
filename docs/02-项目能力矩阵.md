## 一、能力注册表（Capability Registry 原始定义）

这是统一层的**单一事实来源**。每个能力有稳定 ID、明确语义和可测试的验收标准——因为 Task Router 的每一次路由决策都依赖"某 Adapter 是否真的具备该能力"，含糊的能力定义会让 fallback 变成猜测。

### A 组 · 认证与会话

| ID | 能力 | 语义定义 | 验收标准 |
|---|---|---|---|
| `C01` | 账号密码登录 | 用手机号+密码换取有效登录态 | 返回会话，且随后能成功读取课程列表 |
| `C02` | Cookie/Session 持久化 | 会话可落盘并跨进程复用 | 落盘→新进程加载→免登录访问成功 |

### G 组 · Agent 答题链路（v2 新增）

> **变更背景（2026-09-17 用户决策）**：原本计划复用上游 A1 的 AI 答题 provider（在 `config.ini` 配 `endpoint`/`key`）。用户要求改为**由操控 Agent 亲自答题**，即把题目交给操控本平台的 Agent（DeepSeek Agent / 人），由 Agent 产出答案回填。
>
> **实现关键**：A1 的 AI 答题走的是 **OpenAI 兼容协议**。因此统一层只需在本地起一个 OpenAI 兼容的 HTTP 代理，把 `config.ini` 的 `endpoint` 指向 `localhost`，即可让 **A1 零改动地**把题目抛给操控 Agent。这是"零侵入复用"的典范——不改上游一行代码，也不新增协议。

| ID | 能力 | 语义定义 | 验收标准 |
|---|---|---|---|
| `C43` | 题目导出 | 把待答题目（含题型/选项/图片引用）结构化为 Agent 可读载荷 | Agent 能拿到题干、选项、题型；含图题目带可访问的图片引用 |
| `C44` | 答卷注入 | 把 Agent 产出的答案按上游要求的格式回填并触发提交 | 答案被上游接受，答案格式（多选 `A#B#C`）正确 |
| `C45` | 答题-回复循环编排 | 取题 → 等待 Agent → 回填 → 提交的闭环，含超时与部分提交 | 上游等待期间不超时崩溃；Agent 缺席时能降级为"保存不提交" |
| `C46` | OpenAI 兼容代理 | 本地实现 `POST /v1/chat/completions`，把上游请求转成待答工单 | A1 指向 `localhost` 后能把题目送出并拿回答案 |
| `C47` | 待答工单队列 | 待答题目入队/出队/超时，供 Agent 轮询 | 重启后未答工单不丢；超时可配置 |

### H 组 · 签到（v2 新增）

> **变更背景**：用户要求保留签到功能。签到与"刷课"是独立问题域，能力与依赖都不同（需要位置/摄像头/实时监测），因此独立成组，单独排期。

| ID | 能力 | 语义定义 | 验收标准 |
|---|---|---|---|
| `C48` | 签到任务执行 | 完成当前活跃签到（普通签到） | 签到状态变为已完成 |
| `C49` | 签到类型覆盖 | 位置签到、二维码签到、手势签到、拍照签到、签到码签到 | 各类型分别验证可完成 |
| `C50` | 签到监测与通知 | 轮询新签到活动并推送提醒 | 新签到出现后通知可达 |
| `C51` | 签退 | 完成签退 | 状态正确 |

### 矩阵读出来的四个结论

1. **写侧无替代品**：C12/C13/C14/C18 这几条，A1/A2 之外没有可靠实现。A1 是必选项。
2. **读侧唯一优选是 C1（Xuexitong-mcp）**，而且是 MIT。C29/C30/C31 只有它完整覆盖。
3. **C24 图片题只有 A2 一家**（`agents/parser_agent.py` + `solver_agent.py`）。这是 A2 存在的唯一理由，也是 Router 必须做"按能力选 Adapter"而非"固定主备"的直接证据。
4. **C40 暂停 / C42 风控检测：全表为 ○**。这两条**没有任何项目提供**，必须由统一层自建。

## 四、能力缺口明细

| 缺口 | 严重度 | 具体表现 | 处理方案 |
|---|---|---|---|
| **C09 任务点粒度不够** | 🔴 高 | C1 只给"章节 + 进度数字"，**不给单个任务点的类型**。而 `run_video_tasks` / `run_reading_tasks` 这类命令**必须**知道每个任务点是什么类型才能过滤 | 三条路：① 由 Adapter 解析 A1 的内部日志推断；② 扩展读侧 Adapter 解析章节页 HTML（C1 的 README 已给出 `catalog_task`/`icon_yiwanc`/`catalog_points_yi` 的选择器，可行）；③ 降级为"整章执行" |
| **C40 暂停/恢复** | 🟡 中 | 全生态不支持进程内暂停 | 协作式：任务点边界检查标志 → 优雅停止 → 记录断点 → `resume` 时用 `-l 课程ID` 重入，依赖平台"已完成任务点自动跳过" |
| **C04 多账号** | 🟡 中 | 无原生支持 | Orchestrator 层：`{account_id}/` 独立 workdir + 独立 config.ini + 独立子进程 |
| **C42 风控检测** | 🟡 中 | 无法区分"失败"和"被拦截" | 特征库 + 全局限流器；识别后置 `blocked` |
| **C03 重登兜底** | 🟢 低 | 各项目行为不一致 | Orchestrator 统一：调用前探活，失效则重登一次再重试 |
| **C37 日志统一** | 🟢 低 | 格式各异 | 结构化 JSON 日志 + Adapter 侧解析器 |
| **C30 成绩统计** | 🟢 低 | 上游 WAF 已封（C1 实测 403） | 接受：用作业得分 + 考试分数替代 |
